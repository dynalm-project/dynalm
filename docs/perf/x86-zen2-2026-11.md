# x86-64 CPU results: AMD EPYC (Zen 2), AVX2

DynaLM 0.6.0 on an x86-64 CPU against llama.cpp's server, on the same GGUF files and with the same
client. 0.6.0 adds faster AVX2 decode kernels to DynaCore, DynaLM's own CPU engine, and speculative
decoding with EAGLE-3 draft heads.

## Setup

| Item | Value |
|---|---|
| Machine | Cloud server (DigitalOcean Premium AMD): AMD EPYC (Zen 2), 4 vCPU, 16 GB RAM, 2.0 GHz |
| CPU features | AVX2, FMA, F16C |
| Memory bandwidth | 45–57 GB/s read with 4 threads (measured by `dynalm benchmark`) |
| OS | Ubuntu 24.04.5 LTS, kernel 6.8.0 |
| Models | Qwen2.5-1.5B-Instruct, Qwen3-4B and Qwen3-8B, all Q4_K_M |
| llama.cpp | b11695 (commit 9a16f1dbe), `llama-server`, CPU, 4 threads |
| DynaLM | `--mode exact -t 4` (DynaCore kernels) |
| Client | `dynalm benchmark`; `--url` for llama.cpp |
| Workload | 512-token prompt, 128 output tokens, one user, 1 warm-up request |

## Speculative decoding with EAGLE-3

A small EAGLE-3 head, trained for the model, drafts up to 3 tokens from the model's own features;
the full model checks them all in one pass. Every drafted token is checked, so the output is the
same as without drafting. Heads: AngelSlim Qwen3-4B and Qwen3-8B EAGLE-3, their weights quantized
to Q8_0 when loaded.

Time per output token (median), both engines measured in the same session:

| Model | llama.cpp | DynaLM | DynaLM + EAGLE-3 | DynaLM + EAGLE-3 vs llama.cpp |
|---|---|---|---|---|
| Qwen3-4B (`cmp4b.out`) | 127.6 ms | 115.9 ms | 90.7 ms | **1.41×** |
| Qwen3-8B (`cmp8b.out`) | 206.9 ms | 197.2 ms | 154.2 ms | **1.34×** |

Further Qwen3-4B runs with EAGLE-3 measured 69.9–70.6 ms per token (`e8.out`).

```sh
dynalm run qwen3:4b --mode exact --spec-eagle ~/Qwen3-4B_eagle3
```

The Qwen3-8B head is published as `pytorch_model.bin`; DynaLM reads `model.safetensors`, so convert
it first. Qwen2.5-1.5B has no EAGLE-3 head we could verify.

## AVX2 decode kernels

Changes to DynaCore's AVX2 matrix-vector kernels:

- two independent accumulator chains per row;
- a cheaper Q4_K scale/min decode;
- multi-row kernels that compute the activation terms once for up to 8 rows;
- sub-scaled int8 activations also for single-row decode.

Time between tokens (median), DynaLM 0.5.0 and 0.6.0 and llama.cpp in the same session
(`final-*.log`):

| Model | DynaLM 0.5.0 | DynaLM 0.6.0 | Speed-up | llama.cpp | DynaLM 0.6.0 vs llama.cpp |
|---|---|---|---|---|---|
| Qwen2.5-1.5B | 51.6 ms | 39.2 ms | 1.32× | 45.0 ms | **1.15×** |
| Qwen3-4B | 123.4 ms | 93.7 ms | 1.32× | 109.5 ms | **1.17×** |
| Qwen3-8B | 207.0 ms | 160.5 ms | 1.29× | 172.3 ms | **1.07×** |

## Accuracy

Against the fp32 reference (`bench_ppl`, wikitext-2, decode path). DynaLM's rule (DD-053) allows
at most +1% perplexity and 0.0025 mean KL.

| Model | Perplexity, fp32 | DynaLM 0.6.0 | Change | Mean KL |
|---|---|---|---|---|
| Qwen2.5-1.5B | 10.2052 | 10.2254 | +0.20% | 0.00109 |
| Qwen3-4B | 16.1192 | 16.1211 | +0.01% | 0.00047 |

Both pass.
