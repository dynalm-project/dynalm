# x86-64 CPU results: AMD Zen 2, AVX2 (November 2026)

The first DynaLM measurements on an x86-64 CPU. They cover the released DynaLM 0.5.0 and two
development builds of the native CPU engine (DynaCore) that are **not in a release yet**.

**Every run here is uncontrolled.** The machine is a shared cloud VM, and runs with the same
settings varied by up to about 20%. Read the numbers as a direction, not as a confirmed result
under the verdict rule in [benchmarking.md](../benchmarking.md).

Raw data: [data/x86-zen2-2026-11-03/](data/x86-zen2-2026-11-03/) holds both `dynalm cpu-report`
outputs (JSON and Markdown) and `logs.tgz` (benchmark logs, scripts and accuracy logs).

## Setup

| Item | Value |
|---|---|
| Machine | DigitalOcean Premium AMD droplet: AMD EPYC (Zen 2), 4 vCPU, 16 GB RAM, 2.0 GHz |
| CPU features | AVX2, FMA, F16C; no AVX-512, no AVX-VNNI |
| Memory bandwidth | 45–57 GB/s read with 4 threads (measured by `dynalm benchmark`) |
| OS | Ubuntu 24.04.5 LTS, kernel 6.8.0 |
| Models | Qwen2.5-1.5B-Instruct, Qwen3-4B and Qwen3-8B, all Q4_K_M |
| llama.cpp | b11695 (commit 9a16f1dbe), `llama-server`, CPU, 4 threads |
| Client | `dynalm benchmark`; `--url` for llama.cpp |
| Workload | 512-token prompt, 128 output tokens, 1 warm-up request |

## 1. DynaLM 0.5.0 (release): `dynalm cpu-report`

Report: `cpu-report-anonymous-20261102-1632`, 2 rounds, medians. On this CPU the default path
uses ggml's kernels; `--mode exact` uses DynaCore.

Output tokens per second, DynaLM ÷ llama.cpp (above 1 means DynaLM is faster):

| Model | Default, 1 user | DynaCore, 1 user | Default, 4 users | DynaCore, 4 users |
|---|---|---|---|---|
| Qwen2.5-1.5B | 0.91× | 0.76× | 0.81× | 0.86× |
| Qwen3-4B | 0.85× | 0.75× | 0.77× | 0.88× |
| Qwen3-8B | 0.89× | 0.75× | 0.81× | 0.91× |

- llama.cpp is faster on this CPU in every row.
- With 4 users, DynaLM's median first token is sooner (for example 4B: 38.6 s vs 59.1 s), but its
  99th-percentile token gaps are much longer.
- Accuracy against llama.cpp on the same tokens (1.5B): default path 100% top-1, KL 0;
  DynaCore 95.6% top-1, KL 0.0067. Both pass the report's rule.

## 2. Development build: faster AVX2 decode kernels

Changes to DynaCore's AVX2 matrix-vector kernels:

- two independent accumulator chains per row;
- a cheaper Q4_K scale/min decode;
- multi-row kernels that compute the activation terms once for up to 8 rows;
- sub-scaled int8 activations also for single-row decode.

Same machine, same session, `--mode exact -t 4`, before and after (`final-*.log`), with
llama.cpp in the same session:

| Model | Token gap p50, before | After | Change | llama.cpp |
|---|---|---|---|---|
| Qwen2.5-1.5B | 51.6 ms | 39.2 ms | 1.32× faster | 45.0 ms |
| Qwen3-4B | 123.4 ms | 93.7 ms | 1.32× faster | 109.5 ms |
| Qwen3-8B | 207.0 ms | 160.5 ms | 1.29× faster | 172.3 ms |

- After the change, DynaCore generates each token 7–17% faster than llama.cpp on this CPU.
- Prompt reading is still slower than llama.cpp's (first token 7.4 s vs 6.6 s on 1.5B), so
  output tokens per second for one user are equal (10.2, 4.0 and 2.4 tok/s for both engines).
- With 4 users the kernels change little (the 4-user path was already multi-row).

Accuracy against the fp32 reference (`bench_ppl`, wikitext-2, decode path; DD-053 allows
≤ +1% perplexity and ≤ 0.0025 mean KL):

| Model | Perplexity, fp32 | After | Change | Mean KL |
|---|---|---|---|---|
| Qwen2.5-1.5B | 10.2052 | 10.2254 | +0.20% | 0.00109 |
| Qwen3-4B | 16.1192 | 16.1211 | +0.01% | 0.00047 |

Both pass. Before the change the same check gave +0.26% / 0.00098 (1.5B) and +0.16% / 0.00047 (4B).

## 3. Development build: EAGLE-3 speculative decoding on the CPU

The decode kernels above, plus EAGLE-3 speculative decoding with published draft heads
(AngelSlim Qwen3-4B and Qwen3-8B EAGLE-3 heads; the head's weights are quantized to Q8_0 at
load), up to 3 drafted tokens per step (`--spec-eagle <head> --spec-k 3`). Every drafted token
is checked by the full model, so greedy output does not change. One user, time per output token
(TPOT p50):

| Model | llama.cpp | DynaLM, no drafting | DynaLM + EAGLE-3 | Faster than llama.cpp |
|---|---|---|---|---|
| Qwen3-4B, same session (`cmp4b.out`) | 127.6 ms | 115.9 ms | 90.7 ms | 1.41× |
| Qwen3-4B, later runs (`e8.out`) | — | — | 69.9–70.6 ms | 1.54–1.83× against llama.cpp's 108.7–127.6 ms in other runs |
| Qwen3-8B, same session (`cmp8b.out`) | 206.9 ms | 197.2 ms | 154.2 ms | 1.34× |

- Only the same-session rows compare both engines under the same conditions.
- Qwen2.5-1.5B has no trustworthy EAGLE-3 head, so it was not measured.
- Each drafted row costs 30–56% of a one-row step on this CPU, which limits the gain.
- Prompt reading is unchanged, so the time to first token is still slower than llama.cpp's.

## Tests

Linux (this machine) and macOS: all 28 test programs pass on the kernel build and all 29 on
the EAGLE-3 build (`tests.log`, `tests-spec.log`).

## Not measured

- Other x86-64 CPUs: Intel, AVX-512 and AVX-VNNI machines.
- A controlled run (dedicated machine, several rounds, balanced engine order).
- The development builds through `dynalm cpu-report`, and with more than one user for EAGLE-3.
